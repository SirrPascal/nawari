## 3. Session Manager Collection Mechanism Audit

### 3.1 Disproving the SNMP Assumption
Avaya Aura Session Manager (ASM 8.1) documentation confirms that its built-in SNMP daemon exposes:
- **MIB-II** (`1.3.6.1.2.1`): `system`, `interfaces`, `tcp`, `udp`
- **Host Resources MIB** (`1.3.6.1.2.1.25`): processor cores, physical storage, real memory
- **Net-SNMP UCD-SNMP** (`1.3.6.1.4.1.2021`): CPU load, memory buffers
- **Enterprise Trap MIB** (`AV-TRAP-MIB`): asynchronous alarm notifications

**Critical Finding:** Session Manager does **NOT** expose internal SIP Entity Monitoring states or SIP OPTIONS round-trip times through SNMP scalar polling. The previous placeholder OIDs (`1.3.6.1.4.1.6889.2.78...`) have been completely purged from [`provisioning/zabbix/templates/template_nawari_avaya_sm.yaml`](file:///Users/madeira/Desktop/Projects/nawari/provisioning/zabbix/templates/template_nawari_avaya_sm.yaml).

## 5. SBCE EMS Ingestion Pipeline Proof & Specification

Avaya Session Border Controller Enterprise (SBCE 8.1) exposes SIP statistics through its Element Management System (EMS).

### 5.1 Ingestion Architecture
```mermaid
flowchart LR
    SBCE["Avaya SBCE 8.1 Appliance"] -->|Internal IPC| EMS["SBCE EMS Server"]
    EMS -->|HTTPS REST API / CLI export| Ingest["Nawari EMS Collector (`services/voice/avaya/sbce_ems.py`)"]
    Ingest -->|zabbix_sender (JSON)| Zabbix["Zabbix Server Trapper Port 10051"]
    Zabbix -->|Item Values| Dash["Grafana Communication Observability"]
```

### 5.2 Interface Specification
- **Protocol:** HTTPS REST API (`https://<ems-ip>/api/v1/statistics/sip`) or scheduled CLI export (`emscli --stats --sip`).
- **Authentication:** TLS 1.2+ mutual certificate or API service account credentials.
- **Collection Interval:** 60 seconds (dynamic license usage: 1 hour).
- **Sample Source Response Payload:**
```json
{
  "timestamp": "2026-11-08T13:45:00Z",
  "appliance_id": "sbce-pride-01",
  "sip_statistics": {
    "active_calls": 42,
    "active_registrations": 318,
    "active_registrations_tcp": 12,
    "active_registrations_udp": 0,
    "active_registrations_tls": 306,
    "active_srtp_calls": 38,
    "direct_media_calls": 14,
    "dynamic_license_usage_pct": 8.4
  }
}
```
- **Zabbix Trapper Mapping:**
  - `sip_statistics.active_calls` $\longrightarrow$ `avaya.sbce.ems.active_calls`
  - `sip_statistics.active_registrations` $\longrightarrow$ `avaya.sbce.ems.active_registrations`
  - `sip_statistics.active_srtp_calls` $\longrightarrow$ `avaya.sbce.ems.active_srtp_calls`
  - `sip_statistics.direct_media_calls` $\longrightarrow$ `avaya.sbce.ems.direct_media_calls`
  - `sip_statistics.dynamic_license_usage_pct` $\longrightarrow$ `avaya.sbce.ems.license_utilization_pct`
- **Validation Status:** `CONFIGURED_UNVERIFIED` (candidate schema verified, awaiting physical EMS connection).

## 6. Null-Integrity & Upstream Coercion Verification

### 6.1 Audit of Upstream Pipelines
The audit reviewed all 24 dashboard definitions, Zabbix preprocessing configurations, and SQL queries:
1. **No Coalesce-to-Zero:** There are **0 instances** of `COALESCE(metric, 0)` for operational telemetry.
2. **No PromQL Vector-Zero:** There are **0 instances** of `or vector(0)` or artificial series fill.
3. **No Zero-Default Value Mappings:** Value mappings in Grafana preserve `null` as `No Data` or `N/A`.
4. **Zabbix Preprocessing:** JavaScript preprocessing (`return (100 - parseFloat(value));`) fails on null/NaN rather than outputting `0`, ensuring Zabbix marks the item unsupported/missing.
5. **Display State:** Missing data renders as gaps (`spanNulls: False`) or explicit `No data` / `Not collected` strings.
