## 2. Avaya Aura Communication Manager (CM) MIB Conformance

Avaya Aura CM enterprise SNMP metrics reside within the enterprise subtree `1.3.6.1.4.1.6889.2.73` (`avaya.mibs.cm`).

### 2.1 The Official IP Voice Statistics Table: `.8.1.67`
In previous iterations, voice statistics were attributed to provisional tables under `.77` and `.66`. Verification against the official Avaya Aura CM 8.1 MIB confirms that IP voice performance data is consolidated under table **`avCmMeasIpVoStatHrData`** (`1.3.6.1.4.1.6889.2.73.8.1.67`):

- **Command Correspondence:** Maps directly to Avaya System Access Terminal (SAT) report: `list measurements ip voice-stats hourly data`.
- **Underlying Mechanism:** CM aggregates RTP quality metrics into completed 1-hour measurement buckets.
- **Internal Cache:** CM caches this data internally for 600 seconds (10 minutes).
- **Mandatory Polling Limit:** Collector polling frequency must be strictly set to $\ge 1\text{ hour}$ (`delay: 1h` / 3600s). Querying this table more frequently returns identical cached data while consuming call-processing CPU cycles.

#### Detailed Leaf Architecture for Table `.67`:
| Leaf OID | Object Name | Data Type | Semantics & Units | Operational Meaning |
| :--- | :--- | :--- | :--- | :--- |
| `...67.1.1` | `avCmMeasIpVoStatHrNetReg` | `Integer32` | Network Region Identifier | Groups IP endpoints into logical QoS domains (e.g. Region 1 = Pride DC, Region 2 = JKIA). |
| `...67.1.8` | `avCmMeasIpVoStatHrCodec` | `DisplayString` | Codec Name (e.g. G.711A, G.729) | Primary compression codec utilized during the measurement hour. |
| `...67.1.10` | `avCmMeasIpVoStatHrLossPct` | `Gauge32` | Percentage (0–100%) | Percentage of lost RTP voice packets within the network region over the completed hour. |
| `...67.1.11` | `avCmMeasIpVoStatHrPeakJitter` | `Gauge32` | Milliseconds (ms) | Peak packet delay variation recorded during the completed hour. |
| `...67.1.12` | `avCmMeasIpVoStatHrPeakDelay` | `Gauge32` | Milliseconds (ms) | Peak round-trip network transit delay recorded during the completed hour. |
| `...67.1.13` | `avCmMeasIpVoStatHrEchoCancel` | `Integer32` | 1=Active, 2=Inactive | Status of hardware/software echo cancellation on evaluated IP trunks. |

### 2.2 Call Processing Rate Semantics: `.8.1.145`
The call rate table **`avCmListMeasCallRateTotalTable`** (`1.3.6.1.4.1.6889.2.73.8.1.145`) maps to the SAT command `list measurements call-rate total`:

- **Metric Semantics:** Represents an **hourly measurement block**, compiling total completed calls and attempts across the system.
- **The "5-Minute" Rule:** In vendor documentation, 5 minutes is defined as the **strict maximum polling frequency ceiling** (`delay: 5m`). Querying the SAT measurement buffer faster than every 300 seconds risks call processor resource contention.
- **Clarification on Counter Behavior:** This table does **not** expose rolling 5-minute instantaneous attempt rate counters. Total attempts (`.1.2.1`) and completed calls (`.1.3.1`) reflect accumulated hourly blocks. Nawari explicitly notes this semantic in panel descriptions and does not fabricate sub-interval deltas.

### 2.3 Active Alarms Table: `.8.1.5`
The active alarm table **`avCmAlarmsTable`** (`1.3.6.1.4.1.6889.2.73.8.1.5`) reports active hardware, environmental, and software alarms generated by CM:
- `avCmAlarmSeverity` (`.1.2.1`): `1: WARNING`, `2: MINOR`, `3: MAJOR`.
- `avCmAlarmType` (`.1.3.1`): Maintenance object identifier.
- **Polling Limit:** Traversing the alarm table requires tree walking across potentially hundreds of historic entries. Polling is strictly bounded to $\ge 1\text{ hour}$ (`delay: 1h`).

## 3. Avaya G450 Media Gateway Hardware & Event Model

The Avaya G450 Media Gateway is a specialized physical telecommunications appliance terminating E1/ISDN PRI trunks and housing Digital Signal Processors (DSPs) for VoIP transcoding.

### 3.1 Chassis Thermal Model: Discrete Trap Events
Earlier monitoring templates incorrectly assumed a continuous analog thermometer sensor (e.g. reporting degrees Celsius with Warning/Critical analog thresholds). 

G450 Media Gateway Processor (MGP) firmware does not expose an analog thermistor gauge over standard SNMP. Instead, thermal health is governed by discrete trap notifications:
- `temperatureWarning` (Enterprise OID: `1.3.6.1.4.1.6889.2.6.2.1.0.3`): Dispatched when chassis internal sensors exceed safe thermal operating limits.
- `temperatureClear` (Enterprise OID: `1.3.6.1.4.1.6889.2.6.2.1.0.4`): Dispatched when internal fans return temperatures to nominal thresholds.

#### Nawari Event-Derived State Model:
| State Code | Symbolic Name | Source Event / Condition | Operational Interpretation |
| :---: | :--- | :--- | :--- |
| `0` | **`UNKNOWN`** | Initial state or telemetry stale (> 15m without heartbeat) | Gateway thermal status cannot be determined. |
| `1` | **`CLEARED`** | Received `temperatureClear` trap or nominal boot event | Chassis thermal environment is within vendor operating limits. |
| `2` | **`WARNING`** | Received `temperatureWarning` trap | Internal chassis temperature exceeds operational rating. Immediate fan check required. |

*Note:* G450 firmware does **not** produce a distinct "Critical" trap state; critical thermal conditions trigger automatic hardware thermal shutdown protection.

### 3.2 Media Module & DSP Hardware Architecture
The G450 chassis accommodates physical media modules and daughterboard VoIP DSP resources:
1. **Branch Gateways:** Deploy MP20 (20-channel VoIP DSP daughterboard) or MP80 (80-channel VoIP DSP daughterboard).
2. **High-Capacity Gateways:** Deploy MP120 (120-channel) or MP160 (160-channel) daughterboards for high-density core routing.
3. **PSTN / Station Modules:**
   - `MM710`: E1/T1 ISDN PRI interface module (30 channels E1).
   - `MM711`: 8-port universal analog station/trunk module.
   - `MM716`: 24-port high-density analog station module.
   - `MM720`: 8-port ISDN BRI module.

### 3.3 Strict DSP Channel Utilization Gating
Real-time DSP channel utilization cannot be derived from standard IF-MIB interface counters. Collecting accurate DSP utilization requires physical serial number verification, DSP child-board auditing, and MGP CLI trappers.

In accordance with Nawari Telemetry Integrity policies, DSP Channel Utilization is strictly classified as:  
**`NOT_COLLECTED (Hardware Audit Required)`**  
No mock numbers, estimations, or arbitrary percentages are displayed.
